### 0.1.0 – initial feature set

The first public release. The project was developed in ten internal stages before the public history starts; this
section summarises what 0.1.0 contains. Tool descriptions and messages are German.

#### Added

- **MCP server** (stdio, official MCP Python SDK) with about 160 tools, MCP prompts (`netz_doktor`,
  `geraete_aufraeumen`, `sicherheits_check`) and read-only resources (`fritz://{box}/landevices`,
  `fritz://{box}/snapshot/latest`); structured output schemas for the core tools; optional Streamable HTTP transport
  with a mandatory bearer token (`fritzos8-mcp --http`, `--generate-token`, optional TLS, localhost bind by default).
- **Three box interfaces:** TR-064 (generic `tr064_list_services` / `tr064_describe_action` / read-only `tr064_call`
  plus curated tools), the AHA-HTTP interface and the Smart Home REST API (FRITZ!OS ≥ 8.2), and the unofficial
  `/api/v0` REST API of the web UI where TR-064 cannot help. Web login via PBKDF2 (`login_sid.lua?version=2`) with SID
  cache and re-login.
- **Devices & network:** host lists with both device names (TR-064 hostname and web UI `friendly_name`),
  `rename_host`, `set_static_ip`, `delete_host`, Wake-on-LAN, mesh overview, LAN ports with EEE control, online
  monitor, connection quality per device, client-side speed/latency test, box speed test.
- **Wi-Fi:** status and settings per band (channels, auto channel, night control), guest Wi-Fi with time-limited
  sessions, WPS push button, Wi-Fi channel changes, guest Wi-Fi QR code in the separate opt-in `secrets` tier.
- **Telephony:** call list (optionally with phone book names), answering machines, phone books, number registration,
  alarm clocks, call deflections, call barring, dialling helper (critical).
- **Parental controls:** internet access per device, profiles, tickets and online time.
- **Smart home:** AHA devices and statistics, Smart Home REST overview/units/energy report, switches, thermostats,
  boost/window-open, routines, templates, holiday/summer periods, rename/delete, pairing (with AHA fallback for
  FRITZ!OS < 8.2), smart home via TR-064 without web login.
- **NAS & remote access:** NAS status and backup-target check, MyFRITZ!/DynDNS/remote access status, VPN
  (WireGuard/IPSec) and Powerline status, SMB/FTP switches, internet FTP and remote access (critical).
- **Diagnostics:** `network_doctor` (WAN/DSL, event log, Wi-Fi, mesh, link flapping, Raspberry Pi + EEE, DNS single
  point of failure), `security_check` with a 0–100 score and remediation paths, line diagnostics for DSL, fibre and
  mobile, system transparency (TR-069, NTP, IPv6, static routes, forced disconnect), `setup_check` for the box user's
  rights.
- **Monitoring:** local SQLite measurement series per box (`fritzos8-collector`), outage report for the provider
  (`isp_report`), deduplicated alerts with Home Assistant webhook / ntfy / Telegram notifications, anomaly detection
  for creeping degradation, network optimizer with suggestions, guarded apply and before/after effect.
- **Configuration management:** local configuration snapshots and diffs, "FRITZ as code" (`fritz_drift`,
  `fritz_export`, `fritz_apply_*`), device clean-up assistant with vendor lookup, family admin report across boxes.
- **Multiple boxes:** `FRITZ_BOXES` with per-box credentials, optional `box` parameter on every tool,
  `boxes_overview`, `compare_boxes`; plan tokens are bound to their box.
- **Critical system actions** (plan → token → execute): reboot, WAN reconnect, firmware update, static routes, IPv6
  pinholes, port forwards (only to the server's own device via TR-064), Wi-Fi on/off.
- **Packaging & docs:** PyPI metadata and console scripts (`fritzos8-mcp`, `fritzos8-collector`,
  `fritzos8-anonymize`), Dockerfile, experimental Home Assistant add-on template and MQTT bridge (frozen), English and
  German README, generated tool reference (`docs/TOOLS.md`), TR-064 coverage matrix (`docs/COVERAGE.md`),
  compatibility matrix, bilingual mkdocs website, opt-in read-only live test suite, community fixtures via
  `fritzos8-anonymize`, OS keychain support (`keyring` extra).

#### Security

- Read-only by default; writes need `FRITZ_ALLOW_WRITE=1` and are always read back (`verified`); critical actions
  additionally need `FRITZ_ALLOW_CRITICAL=1`, a single-use plan token bound to parameters and target, and – where the
  client supports it – an explicit human confirmation via MCP elicitation.
- The box's two-factor confirmation is never bypassed (`confirmation_required`, `two_factor_status`).
- Central redaction of passwords, SIDs, Wi-Fi keys, VPN keys, tokens, user names, notification URLs and location data
  in every output, error and log; every `/api/v0` response is redacted; optional redaction of serial numbers
  (`FRITZ_REDACT_SERIALS=1`).
- The generic TR-064 caller is read-only and blocks actions that return credentials or risk a lock-out (deny list by
  name, pattern and service).
- Box guard per box: at most two parallel requests, rate limiting and a short read cache that every write clears.
- Credentials only from the environment, files or the OS keychain – never from command-line arguments. Local state
  files are created with mode 0600 in 0700 directories.

#### Known limitations

- Verified live on a FRITZ!Box 7583 (FRITZ!OS 8.26) and 6660 Cable (FRITZ!OS 8.25) for the core read tools and
  selected writes; many later tools are so far only tested against mocks – see `docs/COMPATIBILITY.md` and
  `ROADMAP.md`.
- Not implemented on purpose until a browser capture proves the endpoint: writing DNS/DNSv6 settings and port
  forwards/IPv6 sharing via `/api/v0`.
